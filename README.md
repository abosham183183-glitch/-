# نظام عيادة آمن — نسخة خادم

هذه النسخة تنقل البيانات الحساسة من المتصفح إلى خادم وقاعدة بيانات PostgreSQL.

## ما تم تغييره
- بيانات المرضى والحجوزات والحالات العاجلة محفوظة في PostgreSQL، وليست في `localStorage`.
- تسجيل دخول الدكتور يتم على الخادم فقط.
- البريد المسموح به هو `hmudealali750@gmail.com`.
- كلمات السر مخزنة باستخدام Argon2id، وليس كنص عادي.
- جلسة الدخول تستخدم Cookie من نوع HttpOnly + Secure في الإنتاج + SameSite=Lax.
- حماية CSRF للطلبات التي تغيّر البيانات.
- تحديد عدد محاولات تسجيل الدخول والطلبات العامة (Rate limiting).
- OTP لاستعادة كلمة السر يولد على الخادم، صالح 10 دقائق وبحد أقصى 5 محاولات.
- إرسال البريد يتم من الخادم عبر SMTP؛ لا توجد مفاتيح SMTP داخل HTML.
- صلاحيات لوحة الدكتور مفروضة على الخادم، وليس بمجرد إخفاء زر في الواجهة.
- Helmet مفعّل لإضافة HTTP security headers.

## تشغيل محلياً
1. ثبّت Node.js 20+ وPostgreSQL.
2. انسخ `.env.example` إلى `.env` وضع القيم الحقيقية.
3. نفّذ:
   `npm install`
4. شغّل:
   `npm start`
5. افتح:
   `http://localhost:3000`

## مهم قبل الإنتاج
- غيّر `ADMIN_INITIAL_PASSWORD` إلى كلمة سر قوية وفريدة (12 حرفاً على الأقل، والأفضل أطول).
- استخدم HTTPS فقط عند النشر.
- استخدم PostgreSQL مُداراً مع نسخ احتياطية وتشفير التخزين.
- استخدم مزود SMTP موثوقاً.
- لا تضع `DATABASE_URL` أو `SESSION_SECRET` أو `SMTP_PASS` داخل GitHub أو داخل HTML.
- انشر `server.js` وقاعدة البيانات على خادم، وليس GitHub Pages فقط. GitHub Pages لا يشغّل Node.js API.

## ملاحظة عن حماية البيانات الطبية
لا يوجد موقع يمكن ضمان أنه "غير قابل للاختراق". الهدف هنا هو إزالة نقاط الضعف الأساسية في النسخة التي كانت تعتمد على المتصفح فقط: المصادقة، الجلسات، الصلاحيات، التخزين، والـOTP. يلزم أيضاً تحديث الخادم وقاعدة البيانات ومراجعة أمنية قبل استخدام النظام فعلياً مع بيانات مرضى.
